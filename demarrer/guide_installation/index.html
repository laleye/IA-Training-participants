    Guide d'installation et de dépannage¶

    À faire avant la session 1, en environ 20 minutes. Tous les ateliers se déroulent dans Google Colab, avec un GPU gratuit : vous n'avez rien à installer sur votre ordinateur. L'installation locale (§5) est facultative.

    1. Ce dont vous avez besoin¶

    • Un compte Google (pour Colab et Drive).
    • Un compte Hugging Face (gratuit), indispensable en session 4.
    • Un navigateur récent : Chrome, Edge ou Firefox.
    • Un casque avec micro. On écoute beaucoup de sons pendant les ateliers, et vous enregistrerez votre voix.
    • Un smartphone pour les enregistrements du TP1. Une application d'enregistrement qui produit du WAV, du FLAC ou du M4A suffit.
    • Une connexion stable : au premier lancement, les modèles et les données représentent 0,5 à 2 Go par session.

    2. Créer son compte Hugging Face et un jeton d'accès¶

    1. Créez un compte sur https://huggingface.co/join.
    2. Allez dans Settings → Access Tokens (https://huggingface.co/settings/tokens) et cliquez sur Create new token.
    3. Choisissez le type Write, nécessaire pour publier votre corpus en session 4. Nommez le jeton ia-training-m1 et copiez-le.
    4. Dans Colab, cliquez sur l'icône 🔑 Secrets de la barre de gauche, puis + Ajouter un secret :
    5. Nom : HF_TOKEN
    6. Valeur : votre jeton
    7. Activez Accès au notebook.

    Le secret restera disponible dans tous vos notebooks.

    ⛔ Ne collez jamais votre jeton dans une cellule de code ni dans un document partagé. Si cela arrive, révoquez-le immédiatement sur la page des jetons, puis créez-en un nouveau.

    3. Ouvrir un notebook du cours dans Colab¶

    1. Cliquez sur le badge « Ouvrir dans Colab » en tête du notebook, ou sur le lien envoyé par le formateur.
    2. Menu Exécution → Modifier le type d'exécution : choisissez GPU T4 (« T4 GPU »), puis Enregistrer.
    3. Menu Fichier → Enregistrer une copie dans Drive. Vous travaillez ainsi sur votre copie, sans perdre vos modifications.
    4. Exécutez la première cellule (Installation). Elle installe la bibliothèque du cours, m1utils, en environ 1 minute, puis ne fait plus rien les fois suivantes de la même session.

    Les notebooks existent en version élève, avec des cellules ✍️ À COMPLÉTER, et en version solution. La version solution est diffusée après chaque séance.

    4. Vérifier son environnement : le notebook S0¶

    Ouvrez module1/commun/notebooks/S0_verification_environnement, puis Exécution → Tout exécuter. En environ 5 minutes, il vérifie :

    • les bibliothèques ;
    • le GPU ;
    • la lecture et l'écriture audio ;
    • votre jeton Hugging Face ;
    • les données du cours ;
    • une première reconnaissance vocale ;
    • le format audio de datasets ;
    • en option, votre micro.

    Lisez le rapport final :

    • ✅ Prêt : rien à faire.
    • ⚠️ Prêt pour la session 1, avec des points à régler avant la session 4 : le jeton, parfois le GPU.
    • ❌ Bloquant : suivez la colonne « Action », puis consultez le §7. Si le problème persiste, écrivez sur [CANAL SUPPORT] avant la session 1, en joignant une capture du tableau.

    5. Installation locale (facultative)¶

    Elle est utile si vous avez un GPU NVIDIA, ou pour travailler hors-ligne après les téléchargements.

    # 1. Prérequis : Python 3.11+, git, FFmpeg (Linux : sudo apt install ffmpeg ; macOS : brew install ffmpeg ;
#    Windows : winget install ffmpeg) et uv (https://docs.astral.sh/uv/)
git clone https://github.com/laleye/IA-Training-participants.git && cd IA-Training-participants
uv venv --python 3.12 && source .venv/bin/activate        # Windows : .venv\Scripts\activate
# 2. PyTorch : choisissez la commande adaptée à votre machine sur https://pytorch.org (CUDA, CPU, Apple Silicon)
uv pip install torch torchaudio
# 3. La bibliothèque du cours et ses dépendances
uv pip install -e ".[all,dev]"
python -m ipykernel install --user --name m1 --display-name "IA Training M1"
# 4. Vérification
pytest -q            # ≈ 55 tests verts

    Ouvrez ensuite les notebooks avec Jupyter ou VS Code, noyau « IA Training M1 ». Pour le jeton : export HF_TOKEN=… dans votre terminal, ou un fichier .env non versionné.

    • Apple Silicon (M1–M4) : le GPU s'appelle mps, et m1utils.setup_notebook() le détecte. Certains modèles sont plus lents qu'en CUDA.
    • Sans GPU : tout fonctionne sur CPU, en 3 à 10 fois plus lent. Les ateliers prévoient des prédictions pré-calculées.

    6. Ce qu'il faut savoir sur Colab gratuit¶

    Limite Conséquence Conseil
    Quota GPU variable (quelques heures par jour) message « Vous ne pouvez pas vous connecter au GPU » ne laissez pas tourner de session inutile : Exécution → Déconnecter et supprimer l'environnement
    Déconnexion après inactivité (≈ 90 min) variables perdues relancez les cellules depuis le début ; les téléchargements sont mis en cache
    Disque éphémère /content effacé à la déconnexion sauvegardez vos sorties dans Drive (/content/drive/MyDrive/…)
    Mémoire GPU de 15 Go (T4) CUDA out of memory avec plusieurs gros modèles un modèle à la fois : unload(modele)
    RAM ≈ 12 Go plantage avec de très longs audios segmentez (session 2)

    7. Dépannage¶

    Symptôme Cause probable Solution
    ModuleNotFoundError: m1utils la cellule d'installation n'a pas été exécutée, ou la session a redémarré exécutez la première cellule, puis la suite
    L'installation se termine par « Vous devez redémarrer la session » une bibliothèque déjà chargée a été mise à jour Exécution → Redémarrer la session, puis relancez à partir de la cellule 2
    « Aucun GPU détecté » (⚠️ dans S0) type d'exécution CPU Exécution → Modifier le type d'exécution → GPU T4
    « Impossible de se connecter à un GPU » quota gratuit atteint travaillez sur CPU (les ateliers restent faisables, plus lentement) ou réessayez plus tard
    CUDA out of memory plusieurs modèles en mémoire unload(...) sur les modèles inutilisés, ou Redémarrer la session ; n'utilisez pas simba-s ni simba-w sur un petit GPU
    OSError: Could not load libtorchcodec torchcodec incompatible avec torch ou FFmpeg le cours n'en a pas besoin : m1utils décode avec soundfile. Si l'erreur bloque un import : pip uninstall -y torchcodec
    401 Unauthorized ou 403 sur le Hub jeton absent, de type read, ou pas d'accès à l'organisation vérifiez le secret HF_TOKEN (type write) et l'invitation à l'organisation du cours
    Téléchargement de modèle très lent réseau saturé, nombreux participants en même temps lancez le préchauffage dès l'ouverture ; en dernier recours, prédictions en cache (load_cached_predictions)
    Un fichier audio ne se lit pas (LibsndfileError) format exotique (WhatsApp .opus, .amr) convertissez-le en WAV (application de votre téléphone, ou ffmpeg -i in.opus out.wav)
    Le micro ne s'active pas (S0 partie 8 ou Gradio) permission du navigateur refusée icône 🔒 de la barre d'adresse → Micro → Autoriser ; puis rechargez
    Le Drive n'est pas monté (« mode exemple » dans un TP) drive.mount non exécuté ou mauvais chemin exécutez la cellule de montage ; copiez le chemin depuis le panneau Fichiers (clic droit → Copier le chemin)
    ValueError: … nécessite une langue modèle MMS sans adaptateur load_asr("mms-1b-all", lang="fon") (ou "wol")
    Le noyau redémarre seul mémoire RAM saturée segmentez les longs audios ; fermez les autres onglets Colab
    Le lien Gradio share ne s'ouvre pas réseau d'entreprise qui bloque *.gradio.live partagez votre écran avec l'interface locale

    8. Checklist avant la session 1¶

    • Compte Google et compte Hugging Face créés
    • Jeton Hugging Face write enregistré dans les Secrets Colab (HF_TOKEN)
    • Notebook S0 exécuté, avec un rapport ✅ ou ⚠️ seulement
    • Casque avec micro testé
    • Application d'enregistrement installée sur le smartphone, traitements automatiques désactivés
    • Questionnaire de positionnement rempli

    Pour les formateurs : avant diffusion¶

    • Renseignez tools/config.yaml (github_repo) avec le dépôt public. C'est ce paramètre qui génère les badges Colab et la ligne d'installation de m1utils. Exécutez ensuite make notebooks.
    • Vérifiez les versions sur un Colab récent avec le notebook S0 : les bornes de requirements.txt ont été testées le 2026-10-04 (transformers 5.18, datasets 5.0, gradio 6.29, numpy 2.3).
