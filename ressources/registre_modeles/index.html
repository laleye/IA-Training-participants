    Registre des modèles du Module 1¶

    Source unique des modèles utilisés dans le cours : m1utils.asr.MODEL_REGISTRY. Vérifié sur le Hub Hugging Face le 2026-10-04 (existence, licence, architecture). Mesures réalisées avec transformers 5.18 et torch 2.11 en fp16 sur une GPU de 8 Go (RTX 5060 Laptop) ; sur Colab T4, comptez des temps 1,5 à 2 fois plus longs.

    Autres modèles d'état de l'art cités en cours, sans atelier, faute de support transformers :

    • Omnilingual ASR (Meta, novembre 2025). Plus de 1 600 langues, familles CTC et LLM-ASR jusqu'à 7 G de paramètres. Il s'utilise via le paquet omnilingual-asr (fairseq2), avec des poids publiés sous facebook/omniASR-*. Le fon et le wolof sont couverts : la table officielle de résultats du modèle LLM-ASR 7B (per_language_results_table_7B_llm_asr.csv du dépôt facebookresearch/omnilingual-asr, consultée le 2026-10-04) indique fon_Latn (137,2 h d'entraînement, CER 1,4) et wol_Latn (50,4 h, CER 11,1). Ces scores sont mesurés sur leurs jeux d'évaluation : ils ne sont pas comparables à nos mesures. Évaluer Omnilingual ASR sur testset_s3 est un bon défi 🔴 pour le Module 2.
    • SeamlessM4T-v2 (Meta) : la base de Simba-S.

    4. Résultats de référence sur testset_s3¶

    Le jeu de test commun compte 20 énoncés fon lus (ALFFA), 20 énoncés wolof lus (ALFFA) et 10 énoncés wolof spontanés (Kallaama). Les métriques sont agrégées au niveau du corpus. Les colonnes « norm. » appliquent normalize_text : NFC, ε → ɛ, minuscules, sans ponctuation ni marqueurs. Les chiffres complets sont dans resultats_reference_testset_s3.csv.

    Modèle fon lu WER / CER norm. fon lu WER sans tons wol lu WER / CER wol spontané WER / CER Latence moy. / énoncé
    whisper-small 2,59 / 1,44 2,56 2,42 / 1,45 1,15 / 0,93 3,9 s
    mms-1b-all 0,82 / 0,29 0,41 0,42 / 0,10 0,69 / 0,33 0,15 s
    simba-h 0,27 / 0,09 0,25 0,48 / 0,11 0,60 / 0,27 0,02 s
    simba-m 0,38 / 0,11 0,29 0,40 / 0,09 0,55 / 0,25 0,15 s
    simba-s 0,33 / 0,14 0,22 0,41 / 0,14 0,45 / 0,23 0,4 s
    fon-xlsr 0,12 / 0,04 0,05 1,14 / 0,54 1,06 / 0,66 0,05 s
    wolof-hubert 1,00 / 0,58 1,00 0,02 / 0,01 ⚠️ 0,23 / 0,12 0,02 s

    Lecture pédagogique, à faire découvrir en atelier plutôt qu'à asséner :

    1. Whisper hallucine. Sur le wolof, il produit du devanagari, de l'arabe, de l'hébreu, ou des boucles en français (« ce qu'il s'agit de ce qu'il s'agit… »). Le WER dépasse 100 %.
    2. Les tons pèsent lourd dans le WER. MMS écrit les tons, la référence ALFFA ne les écrit pas. En les retirant, le WER fon de MMS passe de 0,82 à 0,41 : la même sortie vaut deux fois mieux selon la convention d'évaluation.
    3. Un fine-tuning dans le domaine paie. fon-xlsr (300 M) bat tous les modèles multilingues sur le fon lu, mais s'effondre sur le wolof. C'est l'argument du Module 2.
    4. Un score trop beau est suspect. wolof-hubert annonce un WER de validation de 0,36, et nous mesurons 0,02 sur le test ALFFA. Ses données d'entraînement ne sont pas documentées. Hypothèse à vérifier : des énoncés du test ont servi à l'entraîner (contamination).
    5. Le domaine change tout. Tous les modèles se dégradent sur la parole spontanée de Kallaama : hésitations, code-switching, radio.
    6. La taille ne fait pas tout. Simba-H (94 M) rivalise avec des modèles 10 à 15 fois plus gros, pour une latence de 20 ms par énoncé.

    5. Contraintes pratiques¶

    • Mémoire GPU (fp16) : simba-h et wolof-hubert < 0,5 Go ; mms-1b-all et simba-m ≈ 2 Go ; simba-s ≈ 3,5 Go ; simba-w > 7 Go en lot. Libérez toujours la mémoire entre deux modèles avec m1utils.asr.unload(model).
    • Licences. Les modèles MMS sont sous CC-BY-NC-4.0, donc sans usage commercial. Wolof-HuBERT-CTC est sous AGPL-3.0 : un service en ligne qui l'utilise doit publier son code. À discuter dans le TD4 (S4).
    • torchcodec. m1utils décode l'audio avec soundfile et passe des tableaux NumPy aux pipelines : le cours ne dépend pas de torchcodec.

    Points à faire valider¶

    • Données d'entraînement de soynade-research/Wolof-HuBERT-CTC : contacter les auteurs avant d'affirmer une contamination.
